# AI Talk

AI Talk 是一个显式调用的研发需求编译器。它把含糊的人话压缩为可直接执行、可验收的 `RequirementContract 1.0`；“为什么”“前端还是后端”等请求会先进入只读故障定位，UI 异常直接补充浏览器运行态证据。

```text
用户原话
→ 最多 2 个关键澄清问题
→ 最多 3 条任务专属风险
→ 结构化任务契约与验收标准
→ 用户说“执行”
→ 当前代码 Agent 继承契约实施并验证
```

澄清模式不读取或修改代码，不推荐或调用下游 Skill。需求已经明确时，它会跳过提问，直接生成契约。只有用户明确说“执行”“开始执行”或“按这个做”后，当前代码 Agent 才获得修改授权，并继续使用同一份契约，不重新提问。

诊断模式是唯一的只读检索例外：它从用户指定的文件和行号出发，依次检查控制层、数据层和渲染层。遇到不显示、位置异常、遮挡、点击无效或修改后仍未生效等 UI 异常时，AI Talk 直接使用已连接的浏览器检查渲染条件、DOM、尺寸、层级、资源请求和截图。诊断结论与证据进入同一份契约；用户随后说“执行”时直接修复和验证。

```text
$ai-talk:ai-talk 最后一个奖励需要显示领取按钮，修改后还是没有
```

该场景会先确认最后奖励状态及渲染条件，再检查 `btn/receive` DOM、边界与遮挡、资源加载和目标截图；不会先猜 `pt`、`z-index` 或资源 key。

## 安装

```bash
codex plugin marketplace add /绝对路径/ai-talk-public-marketplace
codex plugin add ai-talk@ai-talk-marketplace
```

## 快速使用

```text
$ai-talk:ai-talk 这两部分的用户头像都需要 pag/user 溜光
```

AI Talk 只会确认“这两部分”的范围和 PAG 实例语义，并补齐范围覆盖、多实例循环、列表刷新、点击保持和资源失败降级等验收标准。确认后输出 JSON 契约；用户说“执行”时由当前代码 Agent 直接实施。

完整说明见 [USAGE.md](USAGE.md)。旧的项目检索与 TaskHandoff 路由器保留为 CLI 兼容层，不参与正常 `$ai-talk` 对话。
