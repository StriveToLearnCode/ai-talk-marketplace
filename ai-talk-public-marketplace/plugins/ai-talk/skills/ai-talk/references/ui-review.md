# UI 还原与多语言迁移

把权威对照、页面范围、视觉或语言检查项和验收方式说清楚。设计资料作为视觉基准，现有业务逻辑作为功能基准。

## 必须补充

- Figma、截图、目标语言或其他权威对照来源，以及页面、尺寸和关键状态。
- 代码硬编码文字、语言资源、图片内文案、接口动态内容四类文案来源。
- 尺寸、间距、字体、颜色、背景、切图、布局、长文本和交互状态等相关视觉项。
- 截图、页面对比或明确位置作为差异与验收依据。

只走查或“看看还有哪些没替换”时禁止修改代码。多语言迁移默认不修改业务逻辑；不得自行增加设计稿不存在的内容，不得凭感觉重做视觉。

## 可选 UI 自测路由

页面、组件视觉、样式、布局、交互状态、响应式、截图或 Figma 还原等浏览器可见任务默认不追加浏览器自测。

只有用户明确要求 UI 自测、浏览器检查、Playwright 验证或页面截图对比时，才在最终 `text` 代码块中安排 `$ai-talk:ui-self-check`。普通 UI 修改、Figma、截图或视觉关键词本身不触发；用户要求只走查时写明“只检查不修改”。AI Talk 当前轮不读取或调用该 Skill。

## 截图语义对应

截图、标注图或多张参考图进入话术时，先建立任务相关映射，不要只做文字识别：

- 使用“图片及位置/模块 → 直接可见内容 → 对应需求 → 后续任务指令”描述关系。
- 明确区分现状截图、目标效果、局部细节和参考示例；没有证据时标记待确认。
- 可以根据布局、相邻关系和用户原话归纳模块职责，但要标为 AI 语义判断，不得写成设计稿明示事实。
- 忽略与任务无关的装饰、背景文字和重复内容，不输出完整 OCR 清单。
- 点击区域、状态变化或业务结果无法从截图确定时，不自行补全；只有它会改变任务方向时才追问。

## 紧凑话术骨架

```text
# 任务话术

请走查【页面/活动】从【源语言】迁移到【目标语言】后的遗漏。本轮只分析，不修改代码或业务逻辑。

以【设计稿/截图/目标语言资料】为准，先说明任务相关区域与需求的对应关系，再检查代码文字、语言资源、图片文案和接口动态内容，并核对相关切图、间距、字体、长文本与页面状态。不要增加对照资料中不存在的内容。

请输出遗漏位置、来源类型、判断依据和处理建议。只有用户明确要求浏览器自测时，才在后续执行顺序中调用 $ai-talk:ui-self-check；否则不追加浏览器检查。
```

如果用户只说“优化页面”且没有说明性能、视觉、交互或代码质量方向，只追问一个最影响方向的问题。
