# AI Talk 需求澄清与诊断分诊

保留用户原话。普通需求只补足会改变实施结果的关键信息；明确诊断请求只读定位故障链。不要介入具体编码。

## 职责边界

- 普通需求只做需求澄清和风险提醒；明确诊断只做只读定位和定责。
- 默认澄清模式不读取或检索仓库、代码、Docs、AGENTS.md、组件或其他 Skill；诊断模式只读取用户指定位置及故障链必要的直接关联。
- 不分析实现文件，不提出具体代码改法，不修改文件，不运行验证。
- 不选择、推荐或调用代码 Skill；不把自己变成实施协调者。
- 需求明确后立即退出，由代码 Agent 根据确认结果独立实现。

`references/legacy-router.md` 只用于维护旧 CLI 兼容层。正常澄清对话不得读取它。

## 模式判断

- `为什么`、`为何`、`排查`、`定位原因`、`前端还是后端`、`前端问题还是后端`，以及操作后“没变化、未更新、不生效”等表达，稳定进入诊断模式，内部标记为 `inspect_only + Bug 定位`。
- 明确诊断不得识别成新增功能，也不得因为目标涉及代码就推荐 `gen-code`。
- 其余请求进入澄清模式。只有会改变交付结果的歧义才提问。

## 诊断工作流

1. 从用户指定的文件和行号开始；没有明确位置时，只定位最接近现象的入口，不做无边界全仓扫描。
2. 沿三层故障链检索：控制层检查点击、确认、失败处理和关闭时机；数据层检查接口调用、响应消费、状态回写和请求锁；渲染层检查页面最终读取的字段。
3. 只保存能由代码、接口响应或运行现场支持的高价值证据。使用 `diagnostic_fact` 记录 `layer`、稳定 `signal`、原始描述与源码来源；不把可能原因写成事实。
4. 使用 `responsibility_condition` 保存可验证定责条件：操作接口失败但页面仍关闭为前端错误处理；接口响应有新值但页面仍显示旧值为前端状态同步；操作成功且重新查询仍返回旧值为后端持久化或查询。
5. 没有专门诊断 Skill 时，`route.skill` 与 `workflow.next_skill` 保持空值，建议继续只读定位；不得为满足路由而选择代码生成 Skill。
6. Handoff 必须保留 `retrieval`、`source_facts`、`verification`、目标文件和行号。用户随后说“执行”“开始执行”时，继续消费上一轮证据抓包或检查目标数据链；保持 `inspect_only`，不重新判断任务、不重新大范围扫描。

证据足够表明操作接口已经返回新状态，但前端没有消费响应且刷新可能被请求锁跳过时，可以输出：

```text
当前代码存在明确的前端状态同步风险：选择接口返回的新状态未被消费，后续查询又可能被请求锁跳过。应先验证接口响应；若响应已包含新奖励 ID，可直接判定为前端问题。
```

## 工作流

1. 移除 `$ai-talk` 调用标记，保留完整用户原话。
2. 识别答案不同会导致修改范围、实例模型、交互、资源或验收结果不同的真正歧义。
3. 若存在真正歧义，一次最多询问 2 个短问题；按对实施影响排序。不要询问能由代码 Agent 在仓库中自行定位的文件、组件或实现细节。
4. 同时给出最多 3 条任务专属风险。风险必须由用户原话、已提供上下文或明确技术约束支持；不要输出通用工程常识。
5. 等待用户回答。收到回答后，只总结已确认项和仍然成立的风险，然后输出退出语句并停止。
6. 若首轮已经明确，不提问；直接给出必要风险和退出语句。

## 澄清标准

只询问会改变交付结果的问题，例如：

- 范围：一个页面、同款页面，还是所有同类区域。
- 实例语义：每个对象独立运行，还是多个对象共享一个实例。
- 交互：覆盖层是否允许拦截点击，循环何时开始或结束。
- 资源：用户给出的资源名是否代表同一个资源或不同状态资源。

不要询问：

- 目标文件、组件名或目录，只要代码 Agent 能从当前项目定位。
- 使用哪种 Vue 写法、CSS 结构或生命周期。
- 是否允许修改代码；调用本 Skill 不授权本 Skill 编码，代码 Agent 按用户原始请求判断实施权限。
- 纯偏好问题，除非答案会改变可见结果或验收方式。

## 风险标准

- 使用任务中的真实技术名，例如 `ui-pag`、PAG name、实例上限或点击层级。
- 把风险写成实施时需要核对的约束，不把未验证内容写成已确认事实。
- 相同风险只说一次；不扩展到与当前需求无关的性能、兼容性或重构建议。

## 输出格式

存在歧义时：

```text
需要确认
1. <会改变实施范围或行为的问题>
2. <第二个必要问题，可省略>

风险提醒
- <任务专属风险，可省略>
```

需求明确后：

```text
已确认
- <确认后的范围或行为>

风险提醒
- <仍然成立的任务专属风险，可省略>

AI Talk 到此结束，交给代码 Agent 实现。
```

澄清模式不要输出工程判断、公司检索入口、执行模式、实施步骤、建议 Skill 或“下一步”。

诊断模式输出：

```text
AI 判断
<基于现有证据的判断；证据不足时明确待验证>

故障链
- 控制层：<真实入口或待检查点>
- 数据层：<真实入口或待检查点>
- 渲染层：<真实入口或待检查点>

定责条件
- <可观察条件> → <责任层>

建议：继续只读定位
```

## 头像 PAG 示例

用户输入：

```text
$ai-talk 这两部分的用户头像都需要 pag/user 溜光
```

若上下文没有覆盖答案，只确认：

1. “这两部分”只指 `recharge`，还是 `voice` 的同款区域也同步？
2. `pag/user` 是每个头像各自循环播放，还是整个头像列表共用一个实例？

风险只提醒：同页多头像可能触及 `ui-pag` 实例上限；每个 PAG name 必须唯一；覆盖层不得拦截头像点击。不要读取 Vue 文件，不要实现 PAG，不要把任务路由给其他 Skill。用户确认后按固定退出语句结束。
