# AI Talk v1 试用与指标记录

本文件只定义采集和计算方式，不预填任何试用结果。逐任务数据记录在 `trial-record.csv`。

## 试用要求

- 邀请 2 名 Codex 新用户、2 名重度用户和 1 名负责人或带新人同事。
- 每人至少使用 2 个真实任务，直接输入原本准备交给 Codex 的表达。
- 不提前教授 Prompt 写法；记录用户是否修改话术、是否直接交给 Codex、是否返工和是否再次使用。
- 至少收集 10 个任务，覆盖 Bug、UI/多语言、接口联调三个核心场景，并保留至少 3 个完整前后对比案例。

## 指标口径

| 指标 | 计算方式 | v1 目标 |
| --- | --- | --- |
| 平均追问次数 | Codex 追问次数总和 / 有效任务数 | 不超过 1 次 |
| 首轮理解正确率 | “是否理解正确”为是的任务数 / 有效任务数 | 至少 80% |
| 无需大改比例 | 无修改或只做小改的任务数 / 有效任务数 | 至少 70% |
| 无关修改次数 | “是否修改无关文件”为是的任务数 | 低于直接提问基线 |
| 首轮完成率 | “是否首轮完成”为是的任务数 / 有效任务数 | 与直接提问对比 |
| 一周重复使用率 | 一周内再次使用人数 / 试用人数 | 至少 60% |

## 前后对比

对同类任务分别记录“直接提问”和“使用 AI Talk”的平均追问次数、首轮理解正确率、无关修改次数、首轮完成率、平均沟通轮次和验证方式完整度。没有真实数据时保持空白，不用主观评分代替。

## 观察重点

- 第一条自然语言输入是什么，场景和执行意图是否识别正确。
- 哪些补充被用户保留、删除或改写，是否仍需 Codex 重复追问。
- 是否出现无关修改、无证据结论或需要重复描述背景的返工。
- 只根据真实记录调整规则，优先处理识别错误、输出过长、上下文不贴合和返工接续失败。
