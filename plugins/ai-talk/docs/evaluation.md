# AI Talk 试用与指标

只记录刷新 cachebuster、重新安装插件后的真实新线程任务。逐任务数据记录在 `trial-record.csv`。

## 必测范围

- 覆盖 `direct / discovery` 两条处理路径。
- `direct` 覆盖明确文件修改、Bug 定位和简单代码 review。
- `discovery` 覆盖公司组件、项目复用、接口契约和关键项目事实发现。
- 覆盖 analyze、plan、modify_and_verify、review 四种期望处理方式。
- 覆盖公司组件唯一结果、多个候选、失败、空结果、低相关结果、项目候选和新建本地组件。
- 覆盖严格事实、组件能力与业务需求分离、阻塞性未知和显式建议请求。
- 覆盖 `prompt_state: draft / ready`。

| `direct` 项目命令次数 | 0 |
| `direct` 额外 Skill 调用次数 | 0 |
| `direct` reference 读取次数 | 0 |
| `direct` 未读取项目事实条目数 | 0 |
| 场景识别正确率 | 至少 80% |
| 期望处理方式正确率 | 至少 90% |
| 需要专用 Skill 的 `discovery` 实际调用率 | 100% |
| 不必要的双来源发现次数 | 0 |
| 通用 Skill 错误覆盖专用 Skill 次数 | 0 |
| Skill 结果真实路径或标识率 | 100% |
| 无来源需求条目数 | 0 |
| Assumption 被写成 Fact 次数 | 0 |

| 项目事实来源标注率 | 100% |

简单任务话术保持最小表达，不设置最低字数。

## 记录要求

保存原始输入、处理路径、开始与结束时间、总耗时、用户事实、带来源项目事实、检索事实、阻塞性未知、实际调用 Skill、索引命令、reference 读取、候选与最终话术。逐条检查最终需求是否可追溯到允许来源，不得仅根据文档声明通过。
