# AI 沟通话术

只生成沟通话术，不直接执行话术中的开发任务，除非用户明确要求继续执行。

## 选择场景

- 新页面、新功能、新模块或需求实现：读取 `references/feature-development.md`。
- 报错、异常、功能偶现失效或要求先定位：读取 `references/bug-debugging.md`。
- Figma 还原、视觉验收、切图或多语言检查：读取 `references/ui-review.md`。
- 重构、删除废弃代码、降低重复或整理结构：读取 `references/code-cleanup.md`。
- OpenAPI、接口文档、Mock、请求响应或前后端联调：读取 `references/api-integration.md`。
- 无法确定时，询问用户选择一个场景；不要自行拼接多个模板。

## 工作流程

1. 从用户输入提取背景、资料、目标、限制和验收标准。
2. 读取对应场景模板和 `references/clarifying-questions.md`，判断缺失信息是否会改变实现方向、执行权限或验收结论。
3. 优先从当前对话、仓库文件和已有资料中获取信息；不要询问能够自行读取或合理确认的内容。
4. 存在关键缺口时，只发起一轮不超过三个具体问题。优先调用环境提供的结构化用户输入工具（如 `request_user_input`）展示可点击的单选项；工具不可用时，在聊天正文中使用简短的编号问题和互斥选项降级追问，并允许用户直接补充未覆盖的答案。等待用户回答后再生成话术。用户只给出“做一个弹窗”“修复登录问题”等具体但信息不足的任务时，也必须执行这一步，不能直接输出空白模板。
5. 不存在关键缺口，或用户明确要求“先生成”“按默认处理”“给我空白模板”时，用已知信息替换占位内容；仍无法合理确定的信息标为“待补充”。
6. 最终输出且只输出一个带 `text` 语言标识的完整 Markdown 代码块，将全部话术放在同一个代码块中，使 Codex 可以显示原生的插入输入框箭头。
7. 代码块前只写场景名称；代码块后不追加教程或重复解释。不要拆分代码块，也不要把需要插入输入框的内容放在代码块外。

## 输出与插入

- 依赖 Codex 为 `text` 代码块提供的原生插入箭头；用户点击后，将代码块内的完整话术写入输入框。
- 不要声称已经自动写入输入框，也不要尝试通过技能操作输入框或自动发送话术。

## 智能追问

- 只询问答案不同会导致方案、允许修改范围、执行顺序或验收标准不同的问题。
- 优先级依次为执行权限、目标与预期结果、复现或触发条件、范围与限制、验收方式。
- 每个问题只询问一个决策点，结合用户已经提供的内容具体表述，不使用“请补充更多信息”等泛化问题。
- 优先使用结构化用户输入工具。每题提供 2–3 个简短、互斥且覆盖主要方向的选项，将风险最低或最常见的方案放在第一项并标记为“推荐”；使用结构化工具时不要把“其他”写入选项，客户端会自动提供自由输入入口。
- 每个选项同时提供一句简短说明，说明选择后的行为或影响，避免只列没有上下文的名词。
- 能够归纳为主要方向的缺口，应转换为可选择的单选题，不要先把“弹窗标题和内容、触发方式、按钮行为、代码位置”等字段全部写成“待补充”。无法合理枚举的具体文案、文件路径或业务规则，使用结构化工具时通过客户端自动附带的自由输入入口填写，使用文本追问时允许用户直接补充答案。
- 结构化用户输入工具在当前模式不可用时，不要要求用户切换模式。改用聊天正文发起同一轮文本追问：每题使用编号，选项使用简短标签并附一句影响说明。允许用户回复选项名称或自然语言答案，不要强制使用“1A、2C”等编码格式。
- 不询问技术栈、现有组件、测试命令或相关代码等能够通过读取仓库确认的信息。
- 代码位置应先通过仓库结构、相关页面和已有组件自行判断；只有当前上下文无法访问仓库，或存在多个会显著改变修改范围的合理位置时，才将代码位置作为单选题。
- 不询问仅用于丰富描述、但不影响生成方向的信息；将这类内容标为“待补充”。
- 用户回答后合并前后文重新判断。除非新答案暴露了新的方向性冲突，否则不要连续发起第二轮追问。
- 用户说“先生成”“按默认处理”或拒绝回答时，停止追问，采用风险最低的假设并明确标记待确认项。
- 只有用户明确要求空白模板时，才直接输出带“待补充”字段的模板。用户说出具体功能、问题或模块名称但缺少关键决策时，仍需先发起选择题。

## 统一规则

- 保留“理解任务—执行任务—评估结果”三个阶段。
- 使用明确动作，避免“优化一下”“处理一下”等模糊表达。
- 明确允许修改的范围、禁止事项和开始执行的门槛。
- 要求 AI 区分事实、证据、推测和待确认项。
- 要求 AI 给出可验证结果，而不是只回复“已完成”。
- 用户说“先定位”“先分析”时，必须禁止修改代码。
- 不要编造文件、接口、设计稿、复现结果或业务规则。
