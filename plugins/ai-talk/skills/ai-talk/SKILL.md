# AI Talk

只生成任务提示词。把当前轮视为有依据的需求理解与提示词编译阶段，而不是开发、分析、测试或外部资料读取阶段。

## 不执行原则

无论用户提供文件、截图、Figma、飞书、接口文档或 Skill 名称，都必须遵守：

1. 只允许读取用户明确附带或给出精确本地路径的目标文件，并严格遵守“有界文件读取”。
2. 不读取候选或已选择 Skill 的 `SKILL.md` 正文、reference、脚本或其他资源。
3. 不调用任何下游 Skill、Agent、MCP、浏览器、Chrome、Figma、飞书或网络工具。
4. 不运行 `collect_context.py`、完整能力索引、搜索项目代码或其他项目命令。
5. 不修改文件，不运行 formatter、lint、测试、构建、开发服务器、部署或提交。
6. `$gen-code`、`$ai-test` 等名称只能作为 fenced `text` 代码块中的文本，表示后续 Codex 的执行顺序，不表示当前轮授权。
7. 输出最终提示词后立即停止，只追加固定的未执行声明。

## 有界文件读取

用户附带本地文件或给出精确文件路径时，按输入中的出现顺序处理：

1. 最多读取前 3 个直接指定文件，每个文件最多读取一次、最多 64KB。
2. 用户指定了行号或片段时，优先读取该范围且总量不超过 64KB；否则只读取文件开头 64KB。
3. 第 4 个及之后的文件不读取，在最终提示词中列为后续 Codex 需要读取的材料。
4. 文件不存在、不可读或无法确定精确路径时，不使用 `rg`、`find`、Glob、目录列表或项目扫描寻找替代文件；记录真实失败并交给后续 Codex。
5. 不跟踪 import、require、组件引用或配置引用，不读取同目录文件、`AGENTS.md`、`README.md`、`package.json`、项目配置、Git 状态或直接依赖。
6. 本地附件和精确本地路径属于读取授权；`http://`、`https://`、Figma、飞书及其他 URL 不属于授权，不打开链接或调用外部工具。
7. 只提取与用户需求直接相关的可见结构，例如空模板、已有容器、标签风格、明确字段或当前占位内容。可以基于这些证据归纳其与需求的关系，但不得展开实现、验证兼容性或把语义判断写成文件事实。

## 证据化需求对应

不要把截图或附件当作 OCR 文本仓库。先理解用户希望解决的问题，再只处理与任务相关的内容：

1. `直接证据`：记录用户原话、截图中直接可见的区域或模块、已读取文件的真实结构和 Skill-only 路由结果。截图证据使用可辨认的位置或模块名称定位，不机械抄录全部文字、装饰和无关元素。
2. `AI 语义判断`：基于直接证据归纳模块职责、需求关系和任务目标。每条判断都要能指出依据；它是整理结论，不是新增用户需求。
3. `对应关系`：当存在截图、多个附件、多个模块或多项需求时，按“来源或位置 → 直接可见内容 → 对应用户需求 → 转化后的任务指令”建立映射，并标记为 `明确`、`推导` 或 `待确认`。
4. `建议（非需求）`：可以提出有助于后续执行的可选建议，但必须与用户要求和 AI 语义判断分开。未经用户确认，不得把建议写成必须实现的产品行为、验收标准或技术方案。
5. `待确认信息`：证据不足或存在多个合理对应时，保留真实歧义。只有不同答案会改变任务目标、范围、权限或关键结果时，才追问一个最关键的问题；否则直接生成话术并要求后续 Codex 核实。
6. 多张图片作用不同时，明确标注各自是现状、目标效果、局部细节还是参考示例；没有证据时不得自行指定角色。

纯文本简单任务已经能直接表达目标时，不强制生成空的对应关系或建议段。

## 处理路由

每轮只选择 `direct` 或 `discovery`。

### `direct`

纯文案、语法、明确机械修改、Bug 定位和简单 review 直接生成提示词：

- 项目命令数为 0。
- 基于用户原话和有界读取证据整理目标、范围与任务指令；存在多个来源或模块时补充证据化对应关系。
- 未读取的技术栈、文件内容、组件、接口字段和项目规范不得写成事实。
- 信息足够时一次响应完成，目标 15 秒内。

### `discovery`

新增交互、展示能力、业务逻辑、页面功能或测试任务时，只允许运行一次 Skill-only 索引：

```bash
node <AI Talk Skill 目录>/scripts/build-capability-index.mjs \
  --root <项目根目录> \
  --skills-only \
  --intent <analyze|plan|modify_and_verify|review> \
  --skill-limit 10 \
  --query '<用户原始需求与明确边界>'
```

- 项目根目录使用当前工作区，或直接由用户提供的绝对路径确定；不得扫描项目来寻找根目录。
- 索引只使用 `<项目根目录>/.agents/skills/**/SKILL.md` 的 frontmatter，忽略正文和缺少 `name` 或 `description` 的 Skill。
- `skill_candidates` 只是提示词路由元数据。不得读取候选正文来验证模式，不得调用候选。
- 没有候选时仍生成任务提示词，要求后续 Codex 自行检查适用 Skill；不得改跑完整索引或访问项目文件。
- 除一次 Skill-only 索引和有界目标文件读取外，其他项目命令、业务文件读取、reference 读取、额外 Skill 调用和浏览器调用均为 0。

## Skill 选择与排序

只根据用户事实和索引返回的 frontmatter 选择后续执行 Skill：

- `modify_and_verify` 优先代码生成、局部生成、加逻辑或修改能力，不选择只生成方案的 Skill。
- 用户明确要求测试、测试用例、自动化测试或运行测试时，可增加测试 Skill 作为后续步骤。
- 功能开发与测试同时存在时，先写代码 Skill，再写测试 Skill。若候选分别为 `gen-code` 和 `ai-test`，提示词顺序固定为：
  1. `$gen-code` 使用 `local-patch + incremental` 完成目标范围功能并验证代码。
  2. `$ai-test` 在功能完成后，仅为目标范围生成或执行测试。
- 不因 Vue、Figma、文档等通用词追加通用指南、Figma 分析、文档维护或其他辅助 Skill，除非用户明确要求该独立交付物。
- 只在“已选择能力”中记录真实 Skill 名称、路径、用途和后续顺序，并明确标记“仅写入提示词，尚未调用”。

## 信息边界

最终提示词按以下层次组织：

- `直接证据`：用户原话、附件中直接可见的信息、用户确认内容、最多 3 个明确目标文件的真实结构，以及 Skill-only 索引返回的名称、路径、description 匹配和排序。
- `AI 语义判断`：直接证据支持的归纳、合并、改写和对应结论。必须能回指证据，不得伪装成文件事实或用户原话。
- `建议（非需求）`：有助于执行但尚未得到用户确认的可选判断。必须显式标注，不得转化为硬性实现要求。
- `待确认信息`：证据不足、存在多种合理对应，或会改变任务目标、执行权限、范围和关键业务结果的信息。

不生成未经读取的项目事实，不把 Skill description 中支持的能力扩写成用户需求，不凭空补充业务规则、交互结果、接口字段、验收标准或兼容结论。用户未明确验收标准时，只要求后续 Codex 报告实际验证结果。

## 处理方式

- `analyze`：只分析，不修改。
- `plan`：仅当用户明确要求先给方案或讨论方案时使用。
- `modify_and_verify`：默认方式；后续 Codex 直接修改并验证。
- `review`：只审查，不修改。

用户把提示词交给 Codex 通常是为了执行。除非用户明确要求 `analyze`、`plan` 或 `review`，否则使用 `modify_and_verify`，不得写成“先确认后给方案”。

## 可选 UI 自测 Skill

普通 UI 开发、样式、布局、交互、响应式、截图、Figma 或 Vue 任务默认不追加浏览器自测，目标范围代码验证完成后即可结束。

只有用户明确要求“UI 自测”“浏览器检查”“Playwright 验证”“页面截图对比”或等价独立交付物时，才把插件 Skill `$ai-talk:ui-self-check` 写入最终 `text` 代码块：

- `modify_and_verify` 的后续顺序为功能实现、用户明确要求的目标测试、`$ai-talk:ui-self-check`、PageCenter 配置交接和最终报告；未选择测试 Skill 时省略测试步骤。
- 用户单独要求 UI 审查且不修改时，写入 `$ai-talk:ui-self-check 只检查不修改`，不要安排代码生成 Skill。
- Figma、截图、视觉、Vue、页面或组件等通用词本身不构成 UI 自测授权，不得因此自动追加该 Skill。
- UI 自测所需的 URL、视口、页面状态、参考图和登录信息只保留用户已提供内容；其余交给该 Skill 从真实项目和运行环境确认。
- AI Talk 当前轮只写入固定 Skill 名称和执行目标，不读取 `ui-self-check/SKILL.md`，不调用该 Skill、Playwright MCP、浏览器或 Chrome。

## PageCenter 配置交接

对所有会修改代码的提示词，要求后续 Codex 在完成代码和验证后检查本轮新增或修改的代码是否依赖 PageCenter 配置：

- 需要配置时，不得让用户自行搜索配置项。按 PageCenter tab 列出每个需要新增或修改的 `text`、`json`、`assets`、`components` 或 `props` key，并给出填写值或结构示例、用途、代码消费位置、`新增` / `修改` / `已存在但未验证` 状态和具体操作步骤。
- 无法确认的值标记为 `TODO`，并说明获取来源；不得编造 key、值、PageCenter ID 或远端配置状态。
- 若生成了 `page-center-config.request.json`，同时报告文件路径，但不得只给文件路径而省略人工配置说明。
- 不需要配置时，明确说明“本次不需要新增或修改 PageCenter 配置”。
- AI Talk 当前轮只把本交接要求写入提示词，不检查业务代码中的 PageCenter 依赖，不生成具体配置项，不调用 `gen-page-center-config` 或 PageCenter MCP。

## 最终输出

先输出一屏内的“需求理解与对应”摘要，只显示有值字段：

```text
需求理解与对应：
用户明确需求：
已读取上下文：
AI 语义判断：
对应关系：
建议（非需求）：
待确认信息：
已选择能力：
```

“已读取上下文”只列实际读取的文件路径及直接相关结构；未读取或超过 3 个上限的文件不得写成已验证内容。“对应关系”只列任务相关项，使用“来源或位置 → 直接可见内容 → 对应需求 → 任务指令”的紧凑格式，并注明 `明确`、`推导` 或 `待确认`。

随后只输出一个 fenced `text` 代码块。代码块必须自包含，不依赖摘要也能交给后续 Codex 执行；写入整理后的任务目标、直接证据、AI 语义判断、必要的对应关系、目标范围、后续 Skill 调用顺序、执行模式、边界和待确认信息。建议需要保留时，使用“建议（非需求，不作为必须实现项）”单独标注。Skill 名称即使带 `$` 也只是待复制的提示词文本。

局部功能与测试任务可使用以下结构，空项省略：

```text
请按以下顺序直接完成任务：

整理后的任务目标：
【基于用户原话和证据归纳目标，不新增产品行为】

证据与对应：
- 【明确/推导】<来源或位置>：<直接可见内容> → 对应 <用户需求> → <任务指令>

待确认信息：
【只保留真实歧义；没有则省略】

1. 使用项目 Skill $gen-code（路径：<真实路径>），按 local-patch + incremental 模式修改 <目标文件或范围>。读取实现所需的真实项目上下文、组件注册表和组件文档，优先复用已有能力，不创建平行实现；完成后执行目标范围验证。
2. 功能完成后使用项目 Skill $ai-test（路径：<真实路径>），仅为 <目标范围> 生成或执行测试，不扩散到其他页面。

3. 仅当用户明确要求 UI 自测时，功能和目标范围测试完成后使用插件 Skill $ai-talk:ui-self-check 检查 <目标页面和状态>。默认修复本次范围内问题并复验；用户要求只检查时写明“只检查不修改”。用户未明确要求时省略本步骤。

不要先输出方案，不要修改无关代码。报告实际修改和验证结果。

完成代码和验证后，检查本轮新增或修改的代码是否依赖 PageCenter 配置。如果需要，不得让用户自行搜索配置项；请按 PageCenter tab 列出每个需要新增或修改的 key、填写值或结构示例、用途、代码消费位置、属于新增/修改/已存在但未验证的状态及具体配置步骤。无法确认的值标记为 TODO 并说明获取来源，不得编造；若生成了 page-center-config.request.json，同时提供文件路径，但不能只给文件路径。如果不需要，明确说明“本次不需要新增或修改 PageCenter 配置”。
```

代码块后只显示：

```text
任务话术已生成，当前尚未执行代码修改。
```

不得继续读取、调用或执行，不得输出确认、取消、开始等伪交互文案。
