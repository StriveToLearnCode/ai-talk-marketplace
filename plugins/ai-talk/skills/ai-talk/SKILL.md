# AI Talk

把自然语言研发需求整理成准确、可审查的 Codex 任务话术。AI Talk 负责保留用户事实、调用现有只读发现能力、记录有来源的项目与检索事实并生成最小话术；不替用户补全需求，不修改业务代码，不执行最终开发、构建或测试。

## 固定流程

1. 从当前输入、完整对话、附件、截图、已给路径和项目上下文提取有来源信息，先按“用户事实、项目事实、检索事实、未确认信息”分类。不得把推测写成事实，也不得重复询问已回答的信息。
2. 把当前会话公开的 Available Skills 视为 Skill 发现的权威来源。按 Skill frontmatter 的完整语义选择最小适用集合，专用项目或公司 Skill 优先于通用开发、教学或调试 Skill。
3. 对每个真正适用的 Skill，先说明调用原因，再完整读取其 `SKILL.md` 和该文件要求的必要 reference，随后执行其中与当前任务相关的只读能力发现流程。
4. 不得仅凭词频、路径相似或“前端开发”等宽泛描述调用 Skill。Skill 必须明确覆盖当前任务需要的能力，例如组件检索、历史实现检索、接口契约发现、活动规范或 Vue 活动开发。
5. 被调用 Skill 如要求修改文件、运行最终构建、执行部署或写入外部系统，跳过这些动作，只保留其只读检索步骤。失败或无结果时记录实际检查来源和失败原因；组件开发需求按“公司组件优先流程”处理，不得自动切换到项目组件。
6. 读取 `references/capability-reuse.md`，运行一次 `scripts/collect_context.py --root <项目根目录> --query '<当前需求与已确认补充>'`。用户给出路径时增加 `--related`；明确给出公司目录时增加 `--source-root`。组件开发的公司检索阶段增加 `--defer-project-component-choice`。该脚本只索引项目和显式来源，不替代原生 Skill 调用。
7. 按场景读取 AI Talk 自身 reference，并读取 `references/clarifying-questions.md`。reference 中的执行与验证要求只写入最终话术，不在 AI Talk 阶段实施。
8. 除公司组件优先流程外，把实际调用 Skill 的结果与 `task_context.capabilities` 合并。候选必须保留真实名称、类型、来源、路径或标识和匹配证据；Skill 或组件支持的能力只能作为检索事实，不得扩写成用户需求。
9. 只有推荐方向存在真实歧义时才提问。宿主有结构化选择能力时使用真实选择控件；否则显示编号候选并等待自然语言选择，不输出按钮式文案。
10. `prompt_state == ready` 时直接生成任务摘要和完整任务话术，然后停止。用户后续要求调整时，结合完整对话重新生成；不维护确认、取消或移交状态机。

## 信息来源与事实边界

默认使用严格事实模式。每条进入最终话术的信息必须能归入以下一种来源：

- `用户事实`：用户原话、附件中明确内容或用户后续确认。
- `项目事实`：从真实项目文件读取、与当前任务直接相关的约束。写入时保留来源路径，不得伪装成用户需求。
- `检索事实`：Skill 实际返回的组件名称、标识和匹配证据。它只说明发现了什么。
- `未确认信息`：没有可靠来源的信息。非阻塞项直接省略；只有答案不同会改变任务方向时才提问。

默认不输出 Assumption。只有用户明确要求“补全需求”“给建议”或类似内容时，才可单列“建议（非需求）”；用户确认前不得并入最终任务话术。

严格遵守：`组件支持某能力` 不等于 `本需求要求该能力`。不得因为组件文档存在标题、内容、按钮、关闭方式、props、事件或数据结构，就把这些内容写成用户需求。项目存在 Vue 版本、样式方案或规范，也只有在真实读取、直接相关时才能作为“已验证项目约束”单列，不能写进“用户明确需求”。

## Skill 编排

### 选择优先级

1. 当前项目专用 Skill。
2. 明确覆盖当前能力的公司 Skill。
3. 明确覆盖当前能力的用户 Skill。
4. AI Talk 自身场景 reference 和项目本地索引。

精确能力匹配优先于来源优先级。通用教练、通用前端开发或通用调试 Skill 不得覆盖组件目录、物料平台、历史活动或接口契约等专用 Skill。

## 公司组件优先流程

当用户要求开发、替换或新增可复用 UI 组件，或需求的核心交付物明显是弹窗、表单、列表、选择器等组件能力时，先执行以下流程。不要只依赖用户是否说出“组件”二字。

1. 先读取真实项目上下文，再从 Available Skills 中选择描述明确覆盖公司封装组件、组件目录或物料平台检索的 Skill。不得硬编码 Skill 名称，也不得用通用前端 Skill 代替。
2. 使用用户原始需求、已验证且直接相关的项目约束，以及用户明确给出的目标位置、交互、状态和运行场景构造检索词。除非用户明确给出组件名称，不得加入猜测的组件名或功能。
3. 实际调用该 Skill 的只读检索流程。只有返回真实路径或稳定标识、实际匹配证据且相关性足够的结果，才能成为公司组件候选；关键词建议、无标识结果和 `low_relevance` 结果不能进入候选。
4. 对候选按核心用途、项目约束和使用场景的匹配证据排序。只有一个明显最佳结果、证据覆盖这些维度且没有接近竞争项时，直接标记为推荐采用并进入 `ready`；这只表示推荐确定，不表示代码兼容性已经验证。
5. 证据不足、多个结果接近或适用范围不清楚时进入 `draft`，最多展示三个相关性最高的公司组件。每项只向用户显示“组件名称”和“匹配原因”；路径、来源、风险和待验证内容仅保留给最终话术。
6. 用户选择后才生成最终话术。只写入用户明确需求、所选组件真实名称或标识、直接相关的已验证项目约束，以及“按最小范围验证复用，不扩展未说明功能”的边界。验证不兼容时说明原因并停止，不得自动改用未选择的候选。
7. 用户拒绝全部候选，或没有匹配 Skill、Skill 失败、返回空结果、只返回低相关结果时，明确显示“未找到合适的公司封装组件”，附上真实原因，并只提供“检查当前项目已有实现”或“新建本地组件”两个方向。
8. 用户选择检查项目时，取消项目组件选择延迟，使用本地索引结果执行相同的确定性规则：唯一明确结果直接采用，存在歧义时最多展示三个候选。用户选择新建时，生成限定在当前项目内实现组件的话术，不引入公司组件依赖。

公司检索阶段不得展示、自动采用或用项目本地组件补齐公司候选。`task_context.capabilities.project_component_selection_deferred == true` 时，项目组件和历史实现只作为已收集的内部上下文，不参与当前选择。

### 调用结果

把实际调用结果归一化为：

- `name`：真实能力名称。
- `type`：`skill`、`component`、`utility`、`example`、`project_rule` 或 `prompt`。
- `source`：`project`、`company` 或 `user`。
- `path_or_id`：真实路径、文档地址或能力标识。
- `evidence`：该 Skill 实际返回的匹配原因或查询证据。
- `pending_validation`：只有真实接入需要且与用户明确需求直接相关时，后续 Codex 才需要检查的内容；不得固定罗列组件完整 API。
- `execution_validation`：AI Talk 阶段始终为 `null`。

Skill 只返回建议关键词、没有真实路径或标识时，将结果标记为辅助参考，不得伪装成已发现组件。

### 降级规则

- 没有适用 Skill：说明当前会话没有匹配到专用 Skill；组件开发需求先让用户选择降级方向，其他任务再使用项目本地索引。
- Skill 无法读取或调用失败：保留真实错误摘要和已检查来源；组件开发需求不得静默切换到项目实现。
- Skill 返回空结果：说明该 Skill 已执行但未发现候选，不用低相关结果填充。
- Skill 与项目规则冲突：展示双方、影响和推荐方向，只询问一个会改变任务方向的问题。

## 场景识别

- Bug、报错、异常、偶现、功能失效或定位原因：`bug_debugging`，读取 `references/bug-debugging.md`。
- 截图、Figma、视觉走查、切图或页面还原：`ui_reconstruction`，读取 `references/ui-review.md`。
- 语言迁移、语言包、文案遗漏或图片文字检查：`localization_migration`，读取 `references/ui-review.md`。
- 接口文档、OpenAPI、字段映射或前后端联调：`api_integration`，读取 `references/api-integration.md`。
- 新页面、新功能或新模块：`feature_development`，读取 `references/feature-development.md`。

一个需求可以同时命中多个场景。无法识别时使用 `unknown`，继续按通用任务整理规则处理。

## 期望处理方式

这些值描述最终话术要求后续 Codex 如何处理，不是 AI Talk 当前执行授权：

- `analyze`：只分析，不修改。
- `plan`：先给方案；用户未说明时默认使用。
- `modify_and_verify`：修改并验证。
- `review`：只审查，不修改。

## Prompt 状态

- `draft`：仍有一个会改变方向的阻塞问题，或存在尚未选择的真实复用歧义。
- `ready`：信息足够，可以输出最终任务话术。

只有这两个状态。不存在 `confirmed`、`revise`、确认任务、取消任务或自动执行状态。

## 能力选择与兼容性

- 公司组件或项目组件只有在唯一明确、证据充分且没有接近竞争项时才可自动写入话术。
- 专用 Skill 必须先实际调用；索引中的 `skill_candidates` 只是发现提示，不能直接当作已采用 Skill。
- 公司组件候选最多展示三个，并且只显示组件名称和匹配原因；共享或跨项目能力、同类型多个高相关结果、复用方式不明确时进入待选择状态。
- 用户可将待选项标为 `prefer_reuse`、`prefer_reference` 或 `excluded`。
- `confirmed_reuse`、`partial_reuse`、`incompatible`、`reference_only` 只能由后续 Codex 读取真实代码并验证后给出。
- 不得为了强行复用修改无关公共组件；参考能力不得默认成为项目依赖。

## 准备边界

- AI Talk 每轮只运行一次 `collect_context.py`。用户后续选择检查项目时可在新一轮取消延迟参数；实际调用的专用 Skill 可以按其契约运行必要的只读搜索或查询工具。
- 不修改业务文件，不执行 formatter、lint、测试、构建、开发服务器、部署或提交。
- 不自行展开根因定位或兼容性验证；这些要求写入最终任务话术。
- 不读取 `.env`、密钥、令牌、依赖目录或构建产物，不把整个项目注入话术。
- 只使用真实读取或 Skill 实际返回的事实，不编造路径、组件、接口字段、运行结果或兼容性结论。
- 不编造用户目标、交互、内容、API、实现方式或验收标准；空字段直接省略，不为填满模板生成内容。

## 最终输出

先显示一屏内摘要，只包含实际有值的字段：

```text
用户明确需求：
已验证约束：
已选择能力：
未确认信息：
```

随后输出一个 `text` 代码块，只包含用户事实、直接相关且有来源的项目约束、已选择能力、阻塞性未确认信息和执行边界。用户没有明确验收要求时不得生成验收标准。所有空字段省略，简单任务应保持最小表达，不设置最低字数。

输入“开发一个普通弹窗”时，话术只能保持类似：

```text
请在当前项目中开发一个普通弹窗。仅以用户明确描述和已验证项目约束为准；未说明的交互、内容、API 和实现方式不要自行补全，缺失信息确实会改变实现方向时再提问。
```

代码块后只显示：

```text
任务话术已生成，当前尚未执行代码修改。
```

不得输出“确认任务”“调整任务”“取消”“点击开始”或其他暗示存在交互控件的文案。
