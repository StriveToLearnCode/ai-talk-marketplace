# AI Talk

帮助用户说清楚要做什么，并优先复用已经存在的公司和项目能力。

默认先整理需求并确认一次，确认后让当前 Codex 在同一线程继续处理。只有用户明确要求生成提示词、任务话术、模板或可复制文本时，才只输出话术而不执行任务。

## 工作流程

1. 从用户输入、当前对话和适用指令中提取目标、已知资料、限制、验收结果、执行意图和是否只需话术资产。
2. 读取 `references/capability-reuse.md`。在可访问项目时只运行统一入口：`python3 <AI Talk Skill 目录>/scripts/collect_context.py --root <项目根目录> --query '<用户需求与已确认补充>'`。用户提到明确文件时增加 `--related <路径>`；已知公司目录时增加 `--source-root company-name=<绝对路径>`。
3. 使用统一输出中的 `task_context`：读取项目类型、命令、Git 状态、关键文件和 `capabilities.selected`。复核候选真实文件后确定一个主能力和最多两个辅助能力；没有相关候选时允许不选。正常流程不得再单独运行能力索引后手工拼接上下文。
4. 统一脚本不可运行时，使用 `references/default-preferences.json`，并按需读取 `AGENTS.md`、`README.md`、`package.json`、Git 状态和用户直接提到的文件。仅当 `task_context.capabilities.status` 为 `unavailable` 时，按 capability reference 中的降级方式定向搜索。不要因此阻塞需求整理。
5. 先识别特殊入口，再匹配三个核心场景；未匹配时再使用扩展场景。
6. 读取对应场景 reference 与 `references/clarifying-questions.md`。只保留会提高理解和执行准确度的规则，并与已复核能力的适用条件合并。
7. 只有缺口会改变目标、执行方式、修改范围、能力选择或验收结果时才追问。默认只问一个问题，特殊情况一轮最多三个问题。
8. 用户明确要求“只生成话术”“给我提示词”“保存模板”或同义表达时，直接进入“话术输出”流程。
9. 其他请求进入“确认后继续”流程：展示任务摘要，等待用户选择“继续处理”“只生成话术”或“调整要求”。确认前不得执行任务或修改业务文件。
10. 用户选择“继续处理”后，把已确认摘要和能力组合视为当前任务要求，直接按识别出的执行方式继续处理；不要重复输出完整任务话术，也不要要求用户复制、粘贴或再次描述需求。

## 场景识别

特殊入口优先：

- “还是不行”“没有生效”“问题还在”“上次改错了”“重新看看”“继续排查”：读取 `references/rework-and-template.md`，结合当前对话整理返工摘要；用户只要话术时再生成返工话术。
- 保存、复用、沉淀或变量化有效话术：读取 `references/rework-and-template.md`，只生成模板文本。

核心场景：

- 报错、异常、功能失效、偶现问题或要求定位原因：读取 `references/bug-debugging.md`。
- Figma、截图还原、视觉走查、切图、间距、文案替换或多语言迁移：读取 `references/ui-review.md`。
- OpenAPI、接口文档、Mock、请求响应、字段映射或前后端联调：读取 `references/api-integration.md`。

扩展场景：

- 新页面、新功能或新模块：读取 `references/feature-development.md`。
- 代码审查或风险检查：读取 `references/code-review.md`。
- 重构、删除废弃代码或降低重复：读取 `references/code-cleanup.md`。
- 补单测、集成测试或回归覆盖：读取 `references/test-coverage.md`。
- 技术选型、方向比较或架构讨论：读取 `references/technical-discussion.md`。

存在多个场景时，选择用户当前目标对应的主场景，只吸收必要的次要约束。无法判断且不同理解会改变任务方向时，只问最关键的一个问题。

## 能力发现与组合

- 索引对象包括 Codex/company Skill、Prompt、项目规范、业务组件、composable/hook/util、同类页面和可读的历史示例。
- 只使用真实读取并确认适用的候选。索引评分只用于缩小范围，不是最终事实。
- 一个主能力负责核心工作流；最多两个辅助能力分别补足明确缺口。不要堆叠同义 Skill，也不要为了满足数量强行选择。
- Skill 可调用且适用于当前环境时按其工作流执行；只能读取时提炼其约束，不声称已经调用。组件、函数或同类页面必须写明真实路径和复用点。
- 把能力组合转成当前任务专属要求：优先复用已有 API、状态模型、组件、工具和测试方式；只有确认不适用时才新增，并说明原因。
- 能力之间冲突时，以系统/开发者指令、项目 `AGENTS.md`、用户当前要求和更具体的项目事实为准。

## 执行意图

按保守程度识别执行方式，用户当前明确表达始终覆盖个人配置：

1. **只分析**：“帮我看看”“排查”“先定位”“不要改代码”“先别动”“代码审查”。确认后只分析和定位，不修改代码。
2. **先给方案**：“先给方案”“先分析怎么改”“确认后再做”“先不要直接执行”。确认后先输出原因、方案和影响范围，等待再次授权后再修改。
3. **直接执行**：“直接修复”“帮我改好”“实现并验证”“直接处理”。确认后允许在当前任务范围内修改，完成后说明改动和验证结果。

表达冲突时，禁止修改类措辞优先于先给方案，先给方案优先于直接执行。没有明确表达时，使用有效配置中的 `default_mode`；配置不可用时默认 `plan-first`。不要把默认值描述成用户已经确认的事实。

## 偏好配置

从上下文脚本输出读取有效配置。支持的键和默认值见 `references/default-preferences.json`：

- `language`
- `default_mode`
- `minimal_change`
- `explain_commands`
- `require_verification`
- `avoid_unrelated_files`
- `output_style`

用户配置默认位于 `~/.codex/ai-talk/preferences.json`。未知键忽略并显示配置提示；非法值逐项回退默认值。配置缺失属于正常情况，不显示错误。

偏好影响摘要、话术和后续执行约束，但不扩大任务权限。使用 `language` 指定的语言输出；`minimal_change` 或 `avoid_unrelated_files` 开启时，明确限制无关文件和无依据重构；`require_verification` 开启时要求可复核验证；`explain_commands` 开启时要求简要说明不熟悉或有副作用的命令；`output_style` 只控制话术资产的精简版或增强版长度。

## 项目上下文

- 只使用实际读取的项目事实。先读取项目指令和清单，再读取与当前任务直接相关的页面、组件、接口、测试或工具。
- Skill 和 Prompt 可从项目、常见用户目录、已安装 Codex 插件和显式公司目录发现；公司目录未知时不得猜测固定路径。
- 不读取或展示 `.env`、密钥、令牌、用户隐私、`node_modules`、构建产物或未列入能力来源的任意仓库外文件。
- 不扫描整个项目来制造上下文。相关文件较多时先缩小范围。
- 上下文不足但不影响任务方向时直接生成，并标记“未提供”或“未确认”。

## 确认后继续

默认输出简短、可扫描的任务摘要，不使用代码块：

```text
已识别：【场景】
执行方式：【只分析 / 先给方案 / 直接执行】
任务目标：【期望结果】
相关范围：【涉及模块和明确边界】
验收结果：【可观察结果】
最小改动：【开启 / 关闭】
项目上下文：【已读取关键上下文 / 未读取 / 不适用】
能力复用：【主能力；最多两个辅助能力；复用对象 / 未发现适用能力 / 未检索】
```

摘要只保留会影响执行的内容，不展开逐文件计划。随后优先调用环境提供的结构化用户输入工具，给出以下三个互斥选项：

- **继续处理**：推荐项。确认摘要，并由当前 Codex 立即继续。
- **只生成话术**：转入“话术输出”流程，不执行任务。
- **调整要求**：只追问一个最影响目标、范围、权限或验收的问题；更新摘要后再次确认。

结构化输入工具不可用或当前模式不允许使用时，显示一行“请回复：继续 / 生成话术 / 调整”。不得把完整任务内容放进代码块，也不得要求用户复制粘贴。

用户选择“继续处理”后：

- 将摘要和已读取上下文作为当前任务的已确认要求，直接继续分析、规划或执行。
- 按确认的主能力工作流推进，只在对应环节使用辅助能力；优先复用已确认的组件、函数、Prompt 和规范。
- 遵守当前 Codex 模式、沙箱权限、适用指令和用户授权；确认不能绕过更高优先级限制。
- 不重新展示完整话术，不再次请求相同确认，不把任务转交给用户重新发送。

## 话术输出

仅在用户一开始明确只要话术资产，或在确认步骤选择“只生成话术”时使用。

先输出五行识别反馈：

```text
已识别：【场景】
执行方式：【只分析 / 先给方案 / 直接执行】
最小改动：【开启 / 关闭】
项目上下文：【已读取关键上下文 / 未读取 / 不适用】
能力复用：【主能力；辅助能力；复用对象 / 未发现适用能力 / 未检索】
```

随后只放一个带 `text` 标识的完整代码块。按实际内容选用以下字段，不机械填满：

```markdown
# 任务话术

## 当前问题或需求
## 本轮目标
## 相关范围
## 已知与未确认
## 执行要求
## 输出与验收
```

默认 `concise` 模式下，代码块内任务话术控制在 150–300 个中文字符；简单任务不超过 200 字。删除空字段、重复要求和通用废话。只有任务确实复杂或 `output_style` 为 `enhanced` 时才允许超过 300 字。

代码块后可显示“本次 AI Talk 已补充”，最多五项，只列真实补充内容。确实读取项目时可再显示“本次参考”，最多五项，只列实际读取的关键文件或状态。存在配置警告时显示一行“配置提示”。不要追加 Prompt 教程、评分、底层日志或功能宣传。

场景 reference 中的“话术骨架”只用于这个输出流程；默认确认流程只提炼任务摘要和后续执行约束。

## 统一约束

- 区分用户已确认信息、项目事实、合理默认和未确认信息。
- 不编造文件、技术栈、接口字段、设计内容、运行结果、上一轮结论或业务规则。
- 不编造公司目录、可用 Skill、组件、工具函数或同类实现；未读取候选文件时不得写成已确认复用项。
- 确认前只允许收集上下文和澄清需求，不执行任务或修改业务文件。
- 只分析或只审查时明确禁止修改代码。
- 直接执行也只授权当前任务范围，不扩展为系统权限或无关重构。
- 不把个人风格偏好包装成代码问题，不要求无依据的重构。
- 不把 AI Talk 扩展成 Plan 模式、Git 审计平台、任务管理系统、Prompt 评分器或编辑器。
