# UI 还原与走查

目标是说清对照来源、页面范围、视觉重点和验证方式，不凭空扩展设计。

## 优先补充

- Figma、截图或其他权威对照来源
- 目标页面、设备尺寸、语言和关键页面状态
- 用户关注的切图、间距、字体、背景、布局或交互
- 设计稿与现有业务逻辑各自作为哪类基准
- 只走查、先给修复方案或直接还原
- 截图或页面对比要求

## 话术骨架

```text
# 任务话术

## 当前需求
根据【设计稿/截图】还原或走查【页面与状态】，重点检查【视觉重点】。

## 本轮目标
【执行意图】。设计稿作为视觉基准，现有业务逻辑作为功能基准。

## 相关范围
- 对照资料：【实际提供的链接、截图或版本】
- 页面与尺寸：【已确认范围】
- 相关代码/资源：【实际读取到的内容】

## 执行要求
- 对比尺寸、间距、字体、颜色、背景、切图、布局和交互状态。
- 检查加载、空数据、长文本、不同语言和目标屏幕尺寸中与本次页面有关的状态。
- 不添加设计稿中不存在的内容，不凭感觉重做视觉。
- 差异结论需要截图、页面对比或明确位置作为依据。

## 输出与验收
请说明已确认差异、对应位置、处理建议或改动、对比结果和仍需人工确认项。以【目标页面/尺寸/状态】的对照结果作为验收依据。
```

如果用户只说“优化页面”且没有说明性能、视觉、交互或代码质量方向，应只追问一个最影响方向的问题。
