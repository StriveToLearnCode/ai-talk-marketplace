# 接口联调

目标是明确契约、页面消费方式、状态处理和联调结果，不凭经验补造接口。

## 优先补充

- 权威接口文档、OpenAPI 或真实请求/响应样本
- 联调目标：核对契约、定位异常或完成适配
- 页面实际需要使用的字段和用户结果
- 加载、空数据、业务失败、网络失败等相关状态
- 联调环境和鉴权前提
- 契约差异的输出要求

## 话术骨架

```text
# 任务话术

## 当前需求
对【页面/模块】与【接口】进行联调，目标是【核对/定位/适配结果】。

## 本轮目标
【执行意图】。接口字段以【权威资料】为准，不得自行编造。

## 相关范围
- 接口资料：【文档、OpenAPI 或样本】
- 页面消费：【已知字段和状态】
- 项目上下文：【实际读取到的请求封装、类型或组件】

## 执行要求
- 核对请求方法、路径、参数、响应结构、错误码和鉴权方式。
- 区分文档事实、真实响应、现有代码和仍待确认的差异。
- 关注与当前页面有关的加载、空数据、失败和重复请求状态。
- 不输出令牌、用户隐私或其他敏感数据。

## 输出与验收
请说明字段映射、契约差异、联调或改动结果、验证依据和待服务端确认项。以真实请求响应和页面可观察结果作为验收依据。
```

没有正式契约时，将收集真实请求和响应证据写入任务目标；不要猜测字段后继续生成“已确认”的适配要求。
