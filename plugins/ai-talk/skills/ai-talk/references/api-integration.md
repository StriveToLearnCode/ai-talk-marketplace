# 接口联调

明确权威契约、页面消费方式、必要状态处理和联调证据。不得凭经验编造字段、错误码、鉴权规则或额外业务校验。

## 必须补充

- 项目 OpenAPI YAML、生成的请求与响应类型、真实请求封装，以及联调环境和鉴权前提。
- 请求方法、路径、参数和页面实际消费的响应字段映射；已生成类型不得重复手写。
- 需求明确要求、OpenAPI 明确表达或现有页面已经存在的加载、空数据、业务失败、网络失败、重复点击和重复请求状态；不得默认补齐全部状态。
- 文档、真实响应、现有代码和待服务端确认差异的区分。
- 真实请求响应与页面可观察结果作为验证依据。

项目存在 OpenAPI 时，以 OpenAPI 及其生成类型为权威契约。已声明为 `number` / `integer` 的字段不得降级为 `unknown`，不得使用 `Number()`、`String()`、`parseInt()`、`Boolean()`、`Number.isInteger()`、`> 0` 或 `undefined` fallback 对服务端响应做猜测性标准化。只有契约、用户需求或现有业务规则明确要求时才增加字段校验。

OpenAPI 标记为 nullable 或 optional 时只精确处理允许的 `null` / `undefined`。真实响应违反契约时，报告契约不一致并沿用项目现有错误处理方式，不在消费层静默改成空值或默认值。用户输入、URL 参数、localStorage 和第三方无类型数据仍属于可校验的真实边界。

API 类型直接复用生成类型；一次性响应优先依赖生成客户端和调用链推断。跨文件复用的业务派生类型放在最近模块已有的类型文件；只有没有生成类型且上游确为 `any` / `unknown` 时，才为实际消费字段补最小局部类型，不新建独立类型文件或完整建模未使用字段。

没有正式契约时，把收集真实请求和响应证据写入任务目标；不要猜测字段后继续生成“已确认”的适配要求。不要输出令牌、用户隐私或其他敏感数据。

## 紧凑话术骨架

```text
# 任务话术

请根据项目 OpenAPI YAML、生成类型和真实请求封装直接联调并验证【页面或模块】的【接口】。读取项目中的真实消费方式后完成修改，不要只给方案；只有用户明确要求方案时才停止在方案阶段。AI Talk 本身不修改代码。

以 OpenAPI 及其生成类型为字段依据，核对请求方法、路径、参数、鉴权、响应字段映射和错误码。直接复用生成类型，不把已类型化字段降级为 unknown，不额外转换、normalize、静默 fallback 或增加契约未声明的业务校验。只处理需求明确要求、OpenAPI 明确表达或现有页面已经存在的加载、空数据、失败和重复请求状态。范围限定为当前模块及直接请求封装，不修改无关公共请求代码。

完成实现后报告复用的生成类型、字段映射、契约差异、实际处理的页面状态、待确认项和基于真实请求响应的联调验证结果。响应违反契约时报告问题，不在消费层偷偷修正。
```
