# 重构清理

目标是明确清理动机、行为边界和范围，避免把“优化代码”扩展成无关重构。

## 优先补充

- 需要降低的重复、复杂度、废弃内容或职责混乱
- 允许处理的文件、模块及直接调用方
- 必须保持不变的公开接口、运行行为和兼容性
- 删除候选内容的引用或动态依赖风险
- 执行意图和验证要求

## 话术骨架

```text
# 任务话术

## 当前需求
清理或重构【范围】，主要解决【明确问题】，保持【行为/接口】不变。

## 本轮目标
【执行意图】；允许处理【范围】，不扩展到【排除项】。

## 已知与未确认
- 已知：【实际读取到的职责、依赖或重复模式】
- 未确认：【动态引用、兼容要求等】

## 执行要求
- 只处理有证据的问题，不进行无关命名或架构重做。
- 优先复用现有抽象，不新增无必要依赖。
- 删除前确认静态引用、动态调用和配置依赖。
- 无法证明安全的内容只报告，不删除。

## 输出与验收
请说明清理对象、依据、影响范围、行为兼容结果、验证结果和未处理风险。验收标准是目标问题得到改善且既有行为未发生意外变化。
```

不要把个人风格偏好当成必须修改的问题，也不要替 Plan 模式展开逐步重构计划。
