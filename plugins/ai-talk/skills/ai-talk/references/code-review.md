# 代码审查

目标是明确审查范围和证据标准。默认只审查，不修改代码。

## 优先补充

- 审查的提交、Diff、分支、文件或模块
- 关注的正确性、回归、安全、性能或测试风险
- 已知业务目标和兼容要求
- 发现问题时需要的位置、触发条件和影响说明

## 话术骨架

```text
# 任务话术

## 当前需求
审查【范围】，重点关注【风险方向】。

## 本轮目标
本轮只审查，不修改代码。判断改动是否存在可触发、会影响用户或维护安全的问题。

## 执行要求
- 先理解改动目标和相关上下文，再判断风险。
- 每个问题提供代码位置、触发条件、影响和判断依据。
- 优先报告真实 Bug、回归、数据或安全风险，以及关键测试缺口。
- 不把个人风格偏好、无影响的命名差异或无依据猜测当成问题。

## 输出与验收
按严重程度列出问题；没有发现时明确说明，并指出剩余测试缺口或残余风险。
```

除非用户明确要求后续修复，否则不要在话术中授权代码修改。
