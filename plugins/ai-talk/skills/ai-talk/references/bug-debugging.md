# Bug 定位

```text
你现在先不要修改代码，只做问题定位。

【问题现象】
{{symptom}}

【复现信息】
- 页面/环境：{{environment}}
- 操作步骤：{{steps}}
- 预期结果：{{expected}}
- 实际结果：{{actual}}
- 相关文件或日志：{{evidence}}

【第一阶段：理解任务】
1. 复述问题、触发条件和影响范围。
2. 梳理相关调用链、状态变化、事件和异步时序。
3. 列出当前事实、可能原因和缺少的证据。

【第二阶段：定位问题】
1. 先稳定复现，再通过日志、断点、网络请求或最小实验收集证据。
2. 逐个排除假设，不要把猜测写成结论。
3. 检查是否存在相同模式的潜在问题，但不要修改它们。
4. 在我确认修复方案前，不要修改业务代码。

【第三阶段：评估结果】
请输出复现路径、根本原因、证据、影响范围、最小修复方案、验证方案及发现的同类问题。若仍未确认原因，明确下一步需要补充的证据。
```
