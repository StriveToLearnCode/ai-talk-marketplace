# 新需求开发

目标是把功能诉求、范围和验收结果说清楚，不替 Codex 拆解完整开发步骤。

## 优先补充

- 需求解决的用户问题和期望结果
- 功能入口、核心交互和关键状态
- 设计稿、接口、原型或参考实现
- 项目中可复用的组件、工具或既有模式
- 本轮明确要做和不需要做的内容
- 执行意图与验收方式

## 话术骨架

```text
# 任务话术

## 当前需求
请在【页面或模块】实现【功能】，目标是【用户结果】。

## 本轮目标
【只分析 / 先给方案 / 直接执行】；本轮包含【范围】，不包含【排除项】。

## 相关范围
- 资料：【已提供的需求、设计稿、接口或参考实现】
- 项目上下文：【实际读取到的相关组件、文件或约定】

## 已知与未确认
- 已知：【用户明确内容和项目事实】
- 未确认：【仍会影响结果但当前没有答案的内容】

## 执行要求
- 优先复用项目已有能力，不新增无必要依赖。
- 只处理需求相关范围，不顺手重构无关代码。
- 资料与现有实现冲突时，先说明冲突，不自行扩展需求。

## 输出与验收
请说明最终方案或改动、影响范围、验证结果和仍需确认的内容。验收标准为【可观察结果】。
```

没有设计稿或接口不一定需要追问；只有缺失内容会改变功能方向时才询问。不要凭空增加需求中没有的页面、交互或状态。
