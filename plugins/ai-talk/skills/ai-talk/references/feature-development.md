# 新需求开发

目标是原样保留用户明确提出的功能诉求，只补充有来源且直接相关的项目约束和能力发现，不替用户完善产品定义。

## 信息边界

- 用户明确说出的功能、范围、资料和验收要求属于用户事实。
- 从真实项目文件读取且直接约束当前实现的信息属于项目事实，必须保留来源。
- Skill 返回的组件及其能力属于检索事实，不能自动变成业务要求。
- 用户没有说明的目标、交互、内容、状态、API、样式和验收标准默认省略。

需求核心交付物是组件时，先完成 `capability-reuse.md` 中的公司组件检索与选择流程。未确定公司组件或降级方向前，不生成最终话术；不要在话术骨架中预填任何用户未提到的组件名称。

## 话术骨架

```text
用户明确需求：
【尽量保留用户原话，不扩写目标或功能】

已验证约束：
【仅写直接相关的项目事实及来源；没有则省略整个字段】

已选择能力：
【仅写用户选择或唯一明确采用的真实能力；没有则省略整个字段】

未确认信息：
【只写会改变实现方向的阻塞项；没有则省略整个字段】

执行边界：
仅实现用户明确提出的内容；未说明的交互、内容、API、实现方式和验收标准不要自行补全。按最小范围验证已选择能力，不修改无关代码。
```

用户明确提供验收要求时才增加验收字段。没有设计稿、接口或产品细节不一定需要追问；只有答案不同会改变实现方向时才询问一个最关键问题。

示例：用户只说“开发一个普通弹窗”时，不得补充标题、内容、确认、关闭、props、数据结构、技术栈、样式方案或具体组件名称。
