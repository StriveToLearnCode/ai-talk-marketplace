# 新需求开发

```text
你现在需要协助我完成一个新需求。请先理解任务，再制定计划和修改代码。

【背景】
{{background}}

【相关资料】
- 需求/原型：{{requirement}}
- 设计稿：{{design}}
- 相关文件：{{files}}

【目标】
{{goal}}

【限制】
{{constraints}}

【第一阶段：理解任务】
1. 用自己的话复述需求、用户流程和预期结果。
2. 阅读现有实现，列出可能涉及的页面、组件、状态、接口和资源。
3. 区分已确认内容、合理推断和待确认问题。
4. 如果存在会改变实现方向的问题，先向我确认；否则给出执行计划。

【第二阶段：执行任务】
1. 按确认后的计划实现，优先复用项目现有组件和约定。
2. 只修改需求涉及的范围，不顺手重构无关代码。
3. 每完成一个关键步骤，说明修改位置和原因。
4. 遇到资料与代码冲突时暂停，并说明冲突及建议。

【第三阶段：评估结果】
1. 对照目标逐项检查功能、异常状态和边界情况。
2. 运行项目已有的类型检查、测试或构建命令。
3. 输出修改文件、验证结果、未完成项、风险和人工验收步骤。
4. 不要仅用“已经完成”作为结论。
```
