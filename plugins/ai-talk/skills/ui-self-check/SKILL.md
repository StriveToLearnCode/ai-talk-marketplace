# UI Self Check

实际执行浏览器自测，不生成另一份自测提示词。优先复用当前对话中的目标、改动范围、参考截图、页面状态和验证要求，避免要求用户重复描述。

## 执行模式

- 默认使用 `fix_and_recheck`：发现属于本次任务范围的问题时直接修复，并重新执行受影响的检查。
- 用户明确说“只检查”“只报告”“review”或“不修改”时使用 `review_only`，只报告问题和证据。
- 不修复无关页面、历史问题或需要产品决策的差异；将它们列为剩余风险或待确认信息。

## 准备页面

1. 读取项目实际规则、目标代码、启动方式和与目标页面直接相关的上下文，不猜测命令、路由或登录方式。
2. 优先复用已运行的本地开发服务；没有可用服务时，使用项目真实命令启动并记录地址。不得为了自测修改生产配置或访问未授权环境。
3. 使用已连接的 Playwright MCP 或等价浏览器能力打开目标 URL。只操作本地页面或用户明确授权的测试环境。
4. 优先使用用户提供或参考资料对应的视口和页面状态。用户未指定时，从项目配置、现有测试或页面类型选择有依据的代表视口，并在结果中报告精确宽高。
5. 准备目标状态所需的登录、Tab、数据和交互步骤；无法进入目标状态时，不得用其他页面或静态代码检查冒充浏览器验证。

## UI 自测

只检查本次目标及其直接影响：

- 检查布局、间距、定位、层级、溢出、内容遮挡、页面滚动、响应式和底部安全区。
- 检查本次相关入口、按钮、Tab 或卡片的普通态、选中态、禁用态及点击切换；不得用 DOM 存在代替真实操作。
- 任务涉及吸底导航或多入口切换时，逐项验证入口数量、点击命中、选中反馈、滚动后的固定位置和内容区域不被遮挡。
- 检查图片加载、尺寸和裁切，以及长文本、多语言、空数据和常见动态内容对布局的影响；只覆盖有真实依据的状态。
- 检查本次操作期间的控制台报错、未处理异常和失败请求，区分已有噪音与本次变化造成的问题。
- 有参考截图时，在相同视口和对应页面状态下截图对比。参考图只作为视觉依据；没有精确标注时不得声称像素级完全一致。

## 修复与复验

`fix_and_recheck` 模式下：

1. 只修复能够由浏览器证据证明、且属于本次目标范围的问题。
2. 接口相关修复以项目 OpenAPI YAML、真实请求封装和生成类型为权威契约。不得把已类型化服务端响应字段降级为 `unknown`，不得增加无契约依据的转换、normalize helper、业务校验或静默 fallback；响应违反契约时报告不一致，不在消费层偷偷修正。
3. API 类型直接复用生成类型；一次性响应优先依赖推断。只有没有生成类型且上游确为 `any` / `unknown` 时，才为实际消费字段补最小局部类型。
4. 执行与修改风险相称的代码检查或目标测试。
5. 重新打开或刷新目标状态，复验原问题、相邻交互、控制台和网络结果。
6. 修复没有生效时继续定位真实原因，不得把代码已修改当作页面已通过。

`review_only` 模式下不得修改代码、配置、测试或快照。

## 不可用降级

Playwright MCP、等价浏览器能力、开发服务、测试数据或登录态不可用时：

- 说明具体不可用项和已经尝试的真实步骤。
- 可以执行静态代码检查、类型检查或已有测试作为替代，但明确它们不能证明真实 UI 已通过。
- 列出恢复浏览器验证所需的最小条件，不伪造 URL、截图、操作过程或通过结论。

## 最终报告

报告以下实际结果，只省略不适用项：

- 检查模式、目标范围、URL、视口和页面状态。
- 实际操作步骤及截图路径、截图内容或 DOM/页面结构证据。
- 视觉、交互、滚动、安全区、响应式、图片、长文本和多语言结果。
- 控制台报错、失败请求及其与本次任务的关系。
- 发现的问题、实际修复、代码验证和浏览器复验结果。
- 未执行项、阻塞条件、替代检查和剩余风险。

从 AI Talk 接收的 `modify_and_verify` 任务只要实际修改了代码或配置，最终报告还必须包含 `AI Talk 对账`：逐项标记原目标为已完成、未完成或未验证，列出实际改动范围，并区分浏览器复验、静态检查和未验证项。`review_only` 或用户独立显式调用本 Skill 时不增加该对账块；不得无 scope guard 证据声称范围校验通过。
