# AI Talk

AI Talk 是一个帮助开发者与 AI 更准确沟通的 Codex 插件。它结合个人习惯、项目上下文和通用工作流，将一句模糊需求补全成 AI 容易理解的任务话术，并在结果不理想时帮助生成下一轮返工话术。

> 帮助用户把需求表达清楚，让 AI 少猜测、少跑偏、少重复沟通。

## 它解决什么问题

用户通常知道自己想做什么，但不一定知道怎样把目标、范围、限制和验收方式一次说清楚。AI Talk 会识别任务场景和执行意图，读取必要的项目上下文，只在关键方向缺失时追问，并生成可以直接交给 Codex 的任务话术。

AI Talk 不追求把 Prompt 写长，也不是 Codex Plan 模式的替代品：

```text
AI Talk：帮助用户说清楚要做什么
Plan 模式：帮助 Codex 规划具体怎么做
Codex：执行代码修改
```

## 支持场景

- Bug 定位
- 新需求开发
- UI 还原
- 接口联调
- 代码审查
- 重构清理
- 补充测试
- 技术方案讨论
- 结果不理想后的返工话术
- 有效沟通方式的模板沉淀

## 使用方式

直接输入一句自然语言，不需要先选择模板：

```text
$ai-talk 轮播图偶尔不切换，帮我看看
```

AI Talk 会识别为 Bug 定位和只分析模式，并补充相关范围、证据要求、输出内容和验证方式。最终任务话术会放在单个 `text` 代码块中，方便插入 Codex 输入框。

更多示例：

```text
$ai-talk 帮我实现一个奖励预览弹窗，先给方案
$ai-talk 根据 Figma 还原当前页面，重点检查切图和间距
$ai-talk 帮我优化一下这个页面
$ai-talk 还是不行
```

## 工作方式

1. 识别任务场景。
2. 识别只分析、先给方案或直接执行；未说明时默认先给方案。
3. 按需读取项目说明、技术栈、目录、命令、Git 状态和相关代码。
4. 只在关键内容缺失时追问，最多三个问题，并允许按合理默认继续。
5. 生成简洁、边界明确、可直接使用的任务话术。
6. 结果不理想时结合上一轮上下文生成返工话术。

## 输出原则

- 只补充会影响 AI 理解和执行的信息。
- 不编造文件、技术栈、接口字段、设计内容或验证结果。
- 不修改无关范围，不把个人风格偏好当成代码问题。
- 不生成详细技术实施计划、逐文件修改顺序或复杂任务状态。
- 只展示真实补充的内容和实际读取的项目上下文。
