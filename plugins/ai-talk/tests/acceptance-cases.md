# AI Talk 新线程验收

每个用例在刷新 cachebuster、重新安装插件后的全新 Codex 对话中运行。保存真实输入、Skill 调用说明、工具结果和最终输出。

## 1. 组件需求不预设名称

输入：

```text
$ai-talk 在当前页面开发一个带二次确认、加载态和失败提示的操作入口。
```

前置条件：当前会话提供一个明确覆盖公司组件检索的专用 Skill，同时存在通用前端 Skill。

通过条件：

- 实际调用专用公司 Skill，完整读取其 `SKILL.md` 并执行只读组件检索。
- 查询只包含用户需求、当前项目真实技术约束和使用场景，不加入用户未提到的组件名称。
- 不使用通用前端 Skill 代替专用组件检索 Skill。
- 调用本地上下文时使用 `--defer-project-component-choice`，不展示项目组件。

## 2. 唯一明确的公司组件

让公司组件 Skill 返回一个具有真实标识、用途和项目场景证据的明显最佳结果，且没有接近竞争项。

通过条件：直接采用该结果并生成任务话术；不额外要求选择；明确兼容性仍待后续 Codex 验证；最终话术包含真实标识、来源 Skill、匹配依据以及 props、事件、数据结构、依赖、配置和样式覆盖检查要求。

## 3. 多个公司组件候选

让公司组件 Skill 返回至少四个相关结果，其中前三个相关性接近。

通过条件：`prompt_state` 为 `draft`；最多展示三个候选；每个候选只显示“组件名称”和“匹配原因”；不显示路径、适配项或兼容性结论；用户选择前不生成最终任务话术。

用户选择一个候选后，通过条件：`prompt_state` 变为 `ready`；最终话术只采用所选组件；未选组件不成为依赖；后续验证不兼容时要求说明原因，不自动切换候选。

## 4. 公司组件检索失败或无结果

分别覆盖：当前环境没有组件检索 Skill、Skill 读取失败、调用报错、返回空结果、只返回低相关或无真实标识的结果。

通过条件：显示“未找到合适的公司封装组件”和真实原因；不编造或用低相关结果补位；不自动展示项目组件；只提供“检查当前项目已有实现”或“新建本地组件”。

## 5. 项目检查与本地新建

选择“检查当前项目已有实现”。

通过条件：取消项目组件选择延迟；唯一明确项目组件可直接采用；多个接近结果时最多展示三个组件名称和匹配原因；选择后生成话术并要求验证真实 API 和兼容性。

选择“新建本地组件”。

通过条件：直接生成限定在当前项目内的新组件话术；不引入公司组件依赖；保留项目规范、目标范围和验证要求。

## 6. 用户拒绝公司候选

在公司候选界面中拒绝全部候选。

通过条件：按公司组件无结果处理，显示同样的两个降级方向；不自动采用任何未选择候选。

## 7. Bug 定位

输入：

```text
$ai-talk 轮播图偶尔不切换，先帮我看看，不要修改代码。
```

通过条件：识别 `bug_debugging + analyze`；只调用明确覆盖该排查能力的 Skill；最终话术要求证据和最小定位范围；AI Talk 不运行调试或修改代码。

## 8. 接口联调

输入：

```text
$ai-talk 根据已有接口文档接入榜单接口，不要编造字段。
```

通过条件：识别 `api_integration + modify_and_verify`；实际调用适用的契约或接口 Skill；以真实文档为准；缺失字段列为未确认；不编造接口字段。

## 9. 只生成话术

完成任意 `prompt_state: ready` 任务。

通过条件：显示“任务话术已生成，当前尚未执行代码修改”；AI Talk 不修改业务文件，不运行 formatter、lint、测试、构建或开发服务器，不自动执行最终任务。
