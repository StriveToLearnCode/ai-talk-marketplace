# AI Talk v3 新线程验收

每个用例都在刷新 cachebuster、重新安装插件后的全新 Codex 对话中运行。默认确认路径不得输出完整任务话术代码块；只有显式话术输出用例计算 `text` 代码块字符数。测试结果栏保持空白，实际执行后再填写。

## 1. Bug 定位，确认后只分析

输入：

```text
$ai-talk 轮播图偶尔不切换，先帮我看看
```

首次响应通过条件：

- 场景为“Bug 定位”，执行方式为“只分析”。
- 摘要包含任务目标、相关范围、验收结果、最小改动、项目上下文和能力复用状态。
- 范围包含生命周期、状态、定时器或异步时序，不虚构文件路径或根因。
- 提供“继续处理 / 只生成话术 / 调整要求”三个选择，不输出完整任务话术代码块，不修改文件。

选择“继续处理”后通过条件：

- 当前 Codex 直接开始定位，不要求复制、粘贴或重新发送摘要。
- 使用代码位置、日志、请求、断点或最小实验提供证据和验证方式。
- 严格保持只分析，不修改代码。

结果：未执行

## 4. “还是不行”返工

先在同一对话提供上一轮信息：轮播图被判断为页面隐藏后定时器未恢复，修改了轮播组件并通过单测，但测试环境仍偶尔不切换。随后输入：

```text
$ai-talk 还是不行
```

首次响应通过条件：

- 场景为“返工”，默认先重新定位，再决定是否修改。
- 复用已提供的上一轮判断、修改和验证，不要求重新描述全部背景。
- 摘要覆盖修改是否生效、当前环境是否使用最新代码，以及构建、缓存、部署或启动进程。
- 提供三个确认选择，不重复无证据结论，不虚构新根因。

选择“继续处理”后通过条件：

- 当前 Codex 直接开始重新收集证据和定位。
- 不生成需要重新发送的返工话术。

结果：未执行

## 7. 发现并组合已有能力

准备一个测试项目，至少包含：

- `.agents/skills/debug-carousel/SKILL.md`：要求先收集轮播图生命周期和定时器证据。
- `src/components/Carousel.vue`：已有轮播组件。
- `src/utils/visibility.ts`：已有页面可见性工具函数。
- `src/pages/activity.vue`：真实使用上述组件和工具的同类页面。
- `AGENTS.md`：要求最小改动并运行现有测试。

输入：

```text
$ai-talk 轮播图偶尔不切换，先定位原因，尽量复用项目现有实现
```

首次响应通过条件：

- 先识别为 Bug 定位和只分析，再执行能力检索；任务类型识别不会被能力名称替代。
- 只运行一次 `collect_context.py --query ...`，基础项目上下文和能力组合来自同一个 `task_context`，不分别运行两个脚本后手工拼接。
- 读取候选真实文件后，选择一个主能力和最多两个辅助能力，不把 AI Talk 自身列为候选。
- “能力复用”明确主能力负责的工作流，以及组件、工具函数、同类页面或项目规范中的实际复用对象。
- 不输出完整索引、评分和扫描日志，不编造未读取的公司能力。

选择“继续处理”后通过条件：

- 当前 Codex 按主能力先收集证据，只在对应环节使用辅助能力。
- 优先沿用 `Carousel.vue`、`visibility.ts` 和现有测试方式；确认不适用前不新建重复组件或工具函数。
- 仍然保持只分析，不因发现可复用代码而修改文件。

结果：未执行

自动化契约补充：使用完全相同的需求分别运行两个包含不同项目 Skill 的测试项目，`task_context.capabilities.selected` 必须返回各自项目的能力，不能返回相同的静态组合。

## 8. 无相关能力时降级

在一个只有基础 README、且没有相关 Skill、Prompt、组件或工具的空项目中输入：

```text
$ai-talk 讨论量子光谱校准模块的技术方向，只给方案
```

通过条件：

- 能力索引无相关结果时显示“未发现适用能力”或语义一致的状态，不强行选择通用 Skill。
- 仍按技术讨论和先给方案生成摘要，项目上下文不足处标记未确认。
- 不因为索引为空而阻塞确认流程，不建议创建静态模板来填补结果。

结果：未执行


- AI Talk 不自动展示任务摘要或三个确认选择。
